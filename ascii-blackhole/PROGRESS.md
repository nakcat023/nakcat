## ค้างอยู่ตรงไหน

หยุดหลังวัดความเร็วรอบที่ 3 ซึ่งเป็นการเทียบวิธีแคช glyph ยังไม่ได้สร้างไฟล์ `blackhole.py`
สคริปต์วัดความเร็วอยู่ในโฟลเดอร์ชั่วคราว (scratchpad) ไม่ได้อยู่ในโปรเจกต์ ถ้ารีบูตเครื่องอาจหายไป แต่ผลวัดจดไว้ด้านล่างครบแล้ว

## ผลวัดความเร็ว (เครื่องนี้, หน้าต่าง SCALED 1920x1080, ~12,000 ตัวอักษร)

| สิ่งที่วัด | ms ต่อเฟรม |
|---|---|
| `blits` glyph surface เล็ก ปกติ | 3.4 |
| `blits` glyph surface เล็ก + `BLEND_RGB_ADD` | 3.5–5.6 |
| `blits` จาก atlas ใหญ่ใบเดียว + area rect + ADD | 8.6 (ช้ากว่า ไม่ใช้) |
| `blits` subsurface ของ atlas + ADD | 4.3 |
| สร้างลิสต์ให้ `blits` ด้วย `zip/map` | 1.9 (ถ้าใช้ list comprehension ธรรมดาได้ 3.8) |
| สร้าง glyph surface ใหม่ 1 ใบ (numpy → `make_surface().convert()`) | 0.008 (8 µs) |
| `smoothscale` 480x270 → 1920x1080 | 3.2 |
| `smoothscale` 480x270 → 960x540 แล้ว `scale` → 1920x1080 | 0.8 + 0.45 |
| blit ภาพเต็มจอแบบ ADD | 0.7 |
| `np.bincount` 90k จุด x 3 สี (บัฟเฟอร์แสง) | 1.1 |
| `display.flip()` | 3.0 |

ประมาณเวลาต่อเฟรมทั้งหมดได้ราว 18 ms ซึ่งยังเกิน 16.6 ms ที่ต้องได้สำหรับ 60 FPS เลยต้องเขียนให้ประหยัดตั้งแต่แรก
และต้องทำระบบลด particle อัตโนมัติตามที่สั่งไว้

## ปัญหาที่เจอแต่ยังไม่ได้แก้

1. **หน้าต่างใหญ่เกินจอ**: ถ้าโปรแกรมไม่ได้ตั้งค่า DPI ไว้ Windows จะบอกว่าจอมีขนาด 1536x960 (สเกล 125%)
   หน้าต่าง 1920x1080 จะล้นจอ ทดลองตั้ง `SDL_WINDOWS_DPI_AWARENESS=permonitorv2` ก่อน `pygame.init()` แล้วจอรายงาน 1920x1200 ตามจริง
   หน้าต่าง 1920x1080 จึงพอดีจอ ต้องใส่ค่านี้ใน `blackhole.py` และเผื่อเครื่องที่จอเล็กกว่านี้ด้วย (ย่อหน้าต่างหรือเปิดเต็มจอ)
2. **เวลาต่อเฟรมเกินงบ** (ดูหัวข้อด้านบน) ตัวที่กินเวลามากคือ `blits` ประมาณ 5 ms, `flip` 3 ms และการขยายภาพ glow
3. **ฟอนต์ไทย**: ซอร์สโค้ดมีคอมเมนต์ภาษาไทย ซึ่ง Consolas วาดไม่ได้ ตอนดึงตัวอักษรมาทำทะเลโค้ดต้องเก็บไว้แค่ ASCII 33–126
4. **การสร้าง glyph แบบ lazy อาจทำให้กระตุก**: ตอนระเบิดสีจะเปลี่ยนทั้งจอพร้อมกัน ต้องสร้าง glyph ใหม่หลายร้อยใบในเฟรมเดียว
   (ใบละ 8 µs คิดเป็นประมาณ 5 ms) อาจต้องสร้างสีที่ใช้แน่ๆ ไว้ก่อนตั้งแต่เปิดโปรแกรม

## แบบที่ออกแบบไว้แล้ว (ยังไม่ได้เขียนเป็นโค้ด)

- particle ทุกตัวคือตัวอักษรในตาราง ใช้ array ชุดเดียวกันทั้ง 5 ช่วง สถานะของแต่ละตัวมี
  ATTACHED (อยู่ในตาราง), FREE (ลอยตามฟิสิกส์), SWALLOWED (ถูกกลืน ซ่อนไว้), HOMING (บินกลับเข้าช่องในตาราง), GALAXY
- ช่วง 1: แต่ละคอลัมน์เลื่อนลงอย่างนุ่มในระดับพิกเซลด้วยความเร็วของตัวเอง หัวคอลัมน์สว่างกว่าหาง และมี glitch เป็นแถบที่เลื่อนเยื้องแล้วสลับตัวอักษร
- ช่วง 2: lensing ใช้สูตรเลนส์จุด `r' = (r + sqrt(r² + 4E²)) / 2` แล้วบิดมุมตาม `E/r`
  ใช้ E ราว 1.7 เท่าของรัศมีหลุม ตัวอักษรที่อยู่ในรัศมีหลุมไม่ต้องวาด photon ring วาดเป็นวงบางๆ
- ช่วง 3: ตัวอักษรหลุดจากตารางไล่จากใกล้ไปไกล แรงดึงเป็น GM/r² และ clamp ที่ r_min แต่ละตัวได้ความเร็วแนวสัมผัสเป็น 0.5–0.95 เท่าของความเร็ววงโคจรวงกลม
  ใส่ drag ให้วิ่งเข้าเป็นเกลียว มวลโตตามจำนวนที่กลืน ดิสก์ดูเอียงเพราะบีบแกน y ลงเมื่อใกล้หลุม (ค่อยๆ บีบตามอายุของ particle จะได้ไม่กระโดด)
  ตัวที่วิ่งเร็วเปลี่ยนเป็นตัวขีด `| / - \` ตามทิศความเร็ว และมีหางในบัฟเฟอร์แสง
- ช่วง 4: หลุมหดลง เงียบไป 0.8 วิ แสงวาบ วงคลื่นกระแทกเป็นตัวอักษร แล้ว particle ทุกตัวพุ่งออก
- ช่วง 5: ใช้สปริงที่มีแรงหน่วงพาแต่ละตัวไปยังเป้าบนแขนก้นหอย `r = a·e^(bθ)` โดยเป้าหมุนตาม ω(r) วงในเร็วกว่าวงนอก
  ก่อนวนรอบให้ particle บินกลับเข้าช่องเดิมในตารางประมาณ 2.5 วิ แล้วช่วง 1 จะเริ่มต่อได้เนียน ไม่ต้องตัดฉาก
- คลิกในช่วง 1–3 ได้หลุมดำเล็ก ถ้าเป็นช่วง 1–2 หลุมจะระเหยหายแล้วตัวอักษรบินกลับเข้าตาราง ถ้าเป็นช่วง 3 หลุมเล็กจะถูกดึงไปรวมกับหลุมใหญ่
  คลิกในช่วง 5 เกิดซูเปอร์โนวา ผลัก particle รอบๆ ออกไป แล้วสปริงจะดึงกลับมาเอง
- การวาด: แคช glyph surface ใบเล็กตาม (ตัวอักษร, โทนสี, ระดับความสว่าง) โดยแปลงสีเป็นโทนผ่านตาราง LUT 16³ แล้ววาดด้วย `blits` + `BLEND_RGB_ADD`
  ส่วน glow กับหางยืดวาดลงบัฟเฟอร์ 1/4 ความละเอียดด้วย `np.bincount` เบลอ แล้วขยาย 2 ขั้นก่อนบวกลงจอ
- ฟิสิกส์ใช้ fixed timestep 1/120 วิ และทำได้มากสุด 8 ขั้นต่อเฟรม

## ขั้นตอนถัดไป (เรียงตามลำดับ)

1. เขียนโครง `blackhole.py`: ส่วน CONFIG, ตั้งค่า DPI, เปิดหน้าต่าง SCALED, แคช glyph, ลูปหลักแบบ fixed timestep,
   ตัวเลือก `--seconds`, `--screenshot`, `--start-at` (เอาไว้กระโดดไปเวลาที่ต้องการตอนทดสอบ) และพิมพ์ FPS ตอนปิดโปรแกรม
2. ช่วง 1 แล้วรันแบบไม่เปิดหน้าต่าง (`SDL_VIDEODRIVER=dummy`) เซฟภาพมาดู และวัดเวลาต่อเฟรม
3. ช่วง 2 (lensing, ขอบฟ้าเหตุการณ์, photon ring) แล้วทดสอบ
4. ช่วง 3 (ฟิสิกส์, ดิสก์, spaghettification, จอสั่น) ทดสอบโดยรันจำลองแบบไม่เปิดหน้าต่าง
   แล้วเช็คว่าตัวอักษรถูกกลืนครบภายใน 35 วิ ถ้าไม่ครบให้ปรับ GM กับ drag
5. ช่วง 4 แล้วทดสอบ
6. ช่วง 5 และการวนกลับไปช่วง 1 แล้วทดสอบ
7. ปุ่มควบคุมทั้งหมด, แถบล่าง, หลุมดำเล็ก/ซูเปอร์โนวาจากการคลิก
8. ระบบลด particle อัตโนมัติเมื่อ FPS ต่ำกว่าเป้า (ปิดหางผีก่อน แล้วค่อยลดจำนวนครั้งละ 15% แต่ไม่ต่ำกว่า MIN)
9. รันในหน้าต่างจริง 1920x1080 วัด FPS ทุกช่วง และดูว่าแต่ละช่วงต่อกันลื่น
10. `run.bat` (ห้ามมีภาษาไทย) กับ `README.md` ภาษาไทย

|---|---|---|
